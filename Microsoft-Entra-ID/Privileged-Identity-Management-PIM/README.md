
# Microsoft Entra ID — Privileged Identity Management (PIM)

## Project Overview

This project documents a hands-on Microsoft Entra ID
security lab focused on Privileged Identity Management
(PIM), Just-in-Time (JIT) administrative access, and
identity governance.

The objective was to explore how organisations can
reduce standing privileged access by making
administrative roles eligible for temporary activation.

## Lab Environment

- Microsoft Entra admin center
- Microsoft Entra ID P2
- Microsoft Entra Privileged Identity Management
- User Administrator role
- Microsoft Authenticator
- Authorised Microsoft training tenant

## Security Objectives

1. Configure time-limited eligible administrator access.
2. Review MFA and justification requirements.
3. Activate the User Administrator role through PIM.
4. Verify the resulting privileged access.
5. Validate an authorised group-membership change.
6. Document the security benefits and limitations.

## Implementation

### Stage 1 — Account Preparation
Prepare the authorised test account in Microsoft Entra ID.

### Stage 2 — Eligible Role Assignment
Configure an eligible User Administrator assignment
with a limited assignment window.

### Stage 3 — Activation Security Controls
Review MFA, justification and approval settings.

### Stage 4 — Privileged Role Activation
Activate the role through PIM using the test account.

### Stage 5 — Access Validation
Verify the active role through an authorised
group-membership administration task.

## Security Analysis

This lab demonstrates how Privileged Identity
Management can help reduce standing administrative
privileges through time-limited role eligibility
and controlled activation.

MFA and activation justification provide additional
security safeguards and accountability.

For production environments, further controls may
include approval workflows, access reviews,
privileged activity monitoring and alerting.
